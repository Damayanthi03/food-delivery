I have an existing Food Delivery web application imported from GitHub. I want to upgrade its UI, improve its functionality, and implement proper customer and admin order management.

- First inspect the entire existing project structure, frontend, backend, database, authentication, routes, and current features.

- Preserve the existing technology stack, working features, database schema where possible, and existing source code.

## 2. Modern UI and Theme
Redesign the existing website using a professional food-delivery theme:
- Warm orange/yellow, cream, white, and dark brown/black colors.
- Clean typography, rounded cards, subtle shadows, consistent spacing, and attractive food images.
- Responsive layouts for desktop, tablet, and mobile.
- Professional loading states, empty states, success messages, and error messages.
- Maintain consistent styling across all pages.

## 3. Navigation Bar
Create a consistent navbar with:
- Home
- Restaurants
- Menu
- Reviews
- About Us
- Contact Us
- Cart with a live item count
- Login/Register or user profile, depending on authentication status

Use working navigation links and highlight the active page.

## 4. Restaurant and Menu Pages
- Display a restaurant banner with name, description, rating, delivery time, and other existing data.
- Add food category tabs, such as Combo, Single, Special, Sides, Drinks, and Others, where appropriate.
- Show food cards with images, name, description, price, and Add to Cart button.
- Add search, category filtering, and sorting where supported by the existing data.
- Make Add to Cart, quantity controls, and cart totals functional.
- Prevent duplicate cart entries where the existing cart design expects quantities to be updated.

## 5. Shopping Cart and Checkout
- Display cart items, images, quantities, individual prices, subtotal, and final total.
- Allow customers to increase/decrease quantities and remove items.
- Validate required checkout fields.
- Use the existing backend and order-creation API.
- Show an order confirmation only after the backend successfully creates the order.
- Never claim an order succeeded if the request fails.
- Do not integrate real payments unless the project already supports them or I explicitly request them.

## 6. Customer Portal
Create or improve a customer dashboard accessible to authenticated customers.
Include:
- My Profile
- My Orders
- Order History
- Order Details
- Current Order Status
- Reorder option if supported

A customer must see only their own orders. Display order date, order number, ordered food items, quantities, total amount, delivery details, and status where available.

Persist order history using the existing database and backend. Do not rely only on frontend state or local storage for authoritative order records.

## 7. Admin/Owner Portal
Move the existing all-customer-orders display out of the regular customer-facing pages into a protected Admin/Owner dashboard.

The admin dashboard should include:
- Overview of orders and order statuses.
- All customer orders in a searchable, filterable table.
- Order details, customer information needed to fulfil orders, items, quantities, totals, and timestamps.
- Ability to update order statuses using the statuses supported by the existing backend.
- Clear empty states and error handling.

Only authorized admin/owner accounts may access this dashboard or update order statuses. Implement server-side authorization for admin API endpoints. Hiding admin links in the UI is not sufficient.

Regular customers must never be able to view other customers' orders or modify admin-only data. Do not make every registered user an admin.

## 8. Authentication and Data Integrity
- Reuse the existing authentication system.
- Enforce customer ownership and admin permissions on the backend.
- Validate incoming data and prevent unauthorized order access.
- Keep credentials, API keys, and secrets in environment variables.
- Do not hardcode passwords, expose secrets, or create a public admin account with a known password.
- Preserve existing data and avoid destructive database migrations.
